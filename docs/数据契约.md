# 原始资料契约

所有资料均为本地合成。JSONL一行一条来源观察，row_id仅标识该观察；同业务ID可以在不同revision、批次或接收位置出现。未写revision的静态目录按文件给定值解释，不隐含线上查询。事实字段中的None为缺少来源值，不是零或否。

金额字段以minor结尾时为该币种最小单位整数；数量、位置、时间的单位以字段后缀和政策说明为准。日期为ISO日期；绝对时刻携带偏移；原始received字段决定可见性，不能仅按发生日期提前使用资料。后续业务修改以相同格式输入，不限定样本编号。

## 业务政策

### clock

计划分钟0为2026-11-19 08:00 Asia/Shanghai；全部时间为整数分钟，资源可用区间左闭右开。不可中断工序须整个落在一个可用区间，不能跨休息拼接。 每一资源每个基础班次可在末端延长，最多60分钟且不得跨入下一班次；overtime_max_minutes限制本方案全部资源所用额外工位分钟总和。计划截点取已导入actuals的最晚end_minute，不能在截点以前安排尚未发生工序。

### batching

routes.capacity是单个加工批的最大件数，resources.capacity是并行工位数；每个批占一个工位，时长=duration_setup_min+duration_per_item_min乘该批件数，非染色工序不跨订单合批。dye可跨订单合批，process_version/material/color一致且样品获批，每批最多30件。材料在首道工序按每件1单位消耗，返工在重返步骤按每件0.2单位额外消耗，不把全部原料再扣一遍。实际报工已完成部分的原消耗从来源初始数量扣除。

### labor

资源分钟成本：dye-tank 20，sewing 30，packing 10，carving 40分；加班每分钟另加50分。准备同样收费。延期补偿每订单每逾期分钟100分。共享批次费用按件数分摊，尾差按order_id升序。

### comparison

首先给出是否全守已确认交期的可行结论，能守约时比较总增量成本和最晚完工；不守约的可协商方案按逾期补偿及成本解释，不自动替客户接受。允许多个可行答案，必须给出可核查具体工序时间/数量和成本。

### commit

接受计划必须基于未变化的资源/材料/实际状态；第二份旧状态方案拒绝而非覆盖。发生中的实际工序固定；已完成合格数量只抵一次需求，返工不是新销售数量。 materials同material的最高可见revision替代供给总数量、剩余未领用部分的到货和单价，不改写实际报工已证明领用的部分。资料批次按导入动作形成工坊状态；每个状态有独立revision，scenario.state_revision必须与当前状态一致。后续样品批准、更版和取消记录可用order_id及sample_version提交，批准只适用于该样品版本。

## 资料检查

`python -m unittest discover -s tests -v`只检查资料字节与格式，不是尚未开发业务功能的验收。manifest.json中的摘要对应提交内原始字节，收到后续批次应独立登记来历，不修改旧原始记录。
